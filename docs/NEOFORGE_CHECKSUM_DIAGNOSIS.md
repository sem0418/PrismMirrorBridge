# NeoForge 21.1.265 元数据校验失败：原因定位

日期：2026-11-08。原因定位先以桥接器 1.0.1 验证；修复版本为 **1.0.2**。Prism 源码固定到 **11.1.1 tag**。本轮未访问用户电脑、本机日志或内存，用户后续反馈此版本可用并授权发布；以下保留原因定位和修复验证的范围。

## 用户补充证据及其边界

以下为用户提供的观测，不是本环境直接读取的用户文件：

- 官方旧组件是 **21.1.259**，创建与修改时间均早于桥接器接入；它证明目录曾使用官方元数据，但不是失败的 21.1.265。
- 桥接器配置备份确认其曾完成接入；接入前 MetaURLOverride 不存在。
- 当前磁盘 `net.neoforged/index.json` 创建于接入之后，全文无 sha256。不能将它认作当前官方期望哈希的直接来源，也不能将其无哈希状态当作运行中校验状态已经清除的证据。
- 失败时实际接收到 36042 字节，哈希与桥接器一致；只留下临时下载文件，没有成功落成正式组件文件。
- 取得 21.1.265 官方索引条目的具体启动、磁盘/网络路径，以及用户进程中的具体对象，尚未直接观测。修复和测试针对“当前磁盘索引无哈希，而旧官方哈希仍用于下载校验”这一已证实条件。

## 哈希来源已确认

实际读取 `https://meta.prismlauncher.org/v1/net.neoforged/index.json`，21.1.265 条目的 sha256 为：

`63d850bb1b842adbccb4753027587b5778215c0ed305bdaca080f52e8799021f`

再取得官方 `21.1.265.json`，56449 字节，按原始响应字节计算的 SHA-256 与该值相同。这个期望值来自 Prism 官方组件索引的校验信息，与 CurseForge 模组 ID、JAR 哈希或整合包中的 NeoForge 版本字符串无关。

独立启动当前桥接器，在本环境请求相同组件路径，得到 HTTP 200、36042 字节，实际 SHA-256 为：

`b7542fda4c29695219c27cac053947ea85a691044d0fb17690889540e7dd3ce1`

与用户提供的结果完全一致。桥接器版本索引对应条目确实没有 sha256。官方对象与转换对象在统一 BMCL URL 映射及 releaseTime 格式后，解析后的对象深比较相等；两者各有 45 项 libraries、68 项 mavenFiles，installer SHA1/大小相同。字节差异是可重复的格式与 URL 转换结果；HTTP 200 不意味着它能通过另一份文件的哈希校验。

## Prism 11.1.1 的状态流

1. `meta/JsonFormat.cpp::parseCommonVersion` 从版本索引的非空 sha256 设置 `Meta::Version` 的期望值。
2. `VersionList::merge` 对同 UID/版本重用已有 Version 对象，调用 `Version::mergeFromList`。后者仅在传入哈希非空时覆盖旧哈希；缺字段及空字符串均不清空旧值。
3. 根索引的 `VersionList::mergeFromIndex` 也保留已有非空哈希。旧根索引中保存的包索引哈希可能使旧的官方 `net.neoforged/index.json` 已满足校验，因而不需要请求桥接器的版本索引。
4. `BaseEntity::url` 根据 MetaURLOverride 选择请求地址，但磁盘文件名和元缓存条目仍按 UID/相对路径命名；切换 URL 不会自动建立新的校验状态命名空间。
5. `BaseEntityLoadTask::executeTask` 直接使用版本对象的 `m_sha256` 添加 SHA256 ChecksumValidator。此时可以出现“请求桥接器的转换文件，仍期望官方文件哈希”的组合。
6. 原始 ChecksumValidator 拒绝不同字节；`FileSink::finalize` 在校验器失败时给出 `Failed to finalize validators`。网络重试复用相同期望值，重取同样的转换文件仍会失败。

这不是笼统的“缓存损坏”结论。具体缺陷是元数据源切换后，桥接器转换产物与 Prism 已载入的官方完整性状态混用。`src/prism-config.mjs::configurePrism` 只设置源地址，并假设省略哈希能触发正确刷新；Prism 11.1.1 的合并行为不支持这个假设。

## 验证与边界

- 两份真实 JSON 的完整 64 位哈希及 36042 字节结果已复现。
- Linux C++ 最小诊断执行了从 11.1.1 提取且未修改的两个 merge 函数体，并使用未修改的 ChecksumValidator 头文件：**11 项检查通过**。外围对象为最小测试支架，不是完整启动器运行。脚本会核对上游参考文件的 Git blob SHA 和提取函数体。
- 复现了旧哈希保留、空字符串不清除、三次重新初始化校验仍失败；非空且匹配转换字节的新期望值可覆盖旧值；数据被改动后仍被拒绝。
- 独立 Linux 环境使用**未修改的官方 Prism 11.1.1 可执行文件**做了额外受控响应对照：先让进程载入真实官方索引，再在返回转换组件时把磁盘索引换成已记录的无哈希索引。三次校验失败、正式组件不存在；关闭进程，执行本工具的 `repair-metadata`，重新打开 Prism 后，同一 36042 字节组件通过并成功落成正式文件，SHA-256 仍为 b7542fda4c29695219c27cac053947ea85a691044d0fb17690889540e7dd3ce1。
- 上述测试验证了目标 NeoForge 组件加载。测试服务器对非目标 Minecraft 索引明确返回 404，因此不把它称作完整配置解析、ATM10 导入或进入游戏成功；也不把这个受控顺序当作用户机器的真实历史。
- **该历史定位阶段未在用户电脑实机验证；用户后续已确认 1.0.2 在 Windows 环境正常使用。**
- 无法仅凭用户现有证据判定其官方索引是从磁盘读入，还是在同次运行更早阶段从网络取得。确认具体历史需要保留故障发生前启动器根目录的 `meta/index.json`、`meta/net.neoforged/index.json` 或对应加载日志。

## 1.0.2 的修复与使用

1. 接入、修复、撤销在改变文件前检查 Prism 是否退出。标准进程仍在运行或检测失败时停止，不杀死进程；自定义改名版本需要用户自行确保完全退出。让新进程创建新的对象，避免只改磁盘仍沿用旧校验器。
2. 将整个 `meta` 原子重命名到同目录 `meta.prism-bridge-*`，保留所有旧索引、21.1.259 等组件及临时文件。实例、账号、模组、游戏资源不改动；没有改写官方哈希来匹配别的字节。
3. 原接入备份中的网络配置保留，增加迁移步骤记录。进程中断后重跑可以续办；目录冲突时停止，不覆盖任一副本。这里验证的是进程中断，不保证未落盘操作能在断电后恢复。
4. 对 1.0.0/1.0.1 已接入用户，`05-repair-metadata.cmd` 执行强制隔离；不重复操作 CA 信任。新接入自动隔离，正常重复接入保持已有缓存。撤销时，只有 1.0.2 首次接入明确捕获的原始快照才自动放回；旧版已经混合的缓存保留在备份中，原源重新获取元数据。
5. NeoForge 转换响应仍是原来的 36042 字节。1.0.2 真实 BMCL 转换和本机 HTTP 复测约 22 秒，哈希未变；TLS、模组/游戏文件哈希和原始 Prism 校验器均未禁用。

转换后索引当前仍不发布组件元数据 SHA256；新进程按 Prism 原生的可选哈希语义加载并解析它。此次修复消除跨源校验状态混用，没有建立转换元数据的完整哈希链。最小诊断中“提供正确新哈希可替换旧哈希”是校验行为的对照测试，不代表生产索引已实现这项功能。

升级：完全退出 Prism 和旧工具，把新包解压到新目录，将旧工具的 `config.json` 与 `.bridge` 仅在本机复制过去；运行 `05-repair-metadata.cmd`，选择同一个 Prism 配置文件；再运行 `02-start.cmd` 并重新打开 Prism。配置文件旁的原接入备份应保留。详细撤销与中断说明见 README。

70 项离线检查包含 16 项新增迁移测试：无哈希索引和临时文件保留、运行中拒绝、重复接入、旧版升级、撤销、进程中断续办、目录冲突、符号链接拒绝与路径约束。CLI 另从带空格路径执行接入/修复/撤销，确认原始快照恢复。

原始记录：`test-results/neoforge-checksum-diagnosis.json`（1.0.1 定位）、`user-observations-neoforge.json`（用户提供证据）、`prism-hash-state-1.0.2.json`（11 项最小诊断）、`official-prism-checksum-1.0.2.json`（官方 Linux 可执行文件的受控对照）和 `neoforge-live-1.0.2.json`（真实 BMCL 转换）。本修复没有将任何网络失败或校验失败改报成功。
